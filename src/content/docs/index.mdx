## Cluster Overview 📊

The Proxmox Atlas cluster is designed as a **3-Node Homogeneous Small-Form-Factor (1L) High Availability (HA)** homelab setup on the `192.168.1.0/24` management network[cite: 2].

* **Quorum Model**: 3 Physical Nodes (3 total votes)[cite: 2].
* **Quorum Threshold**: 2 votes required to maintain write quorum[cite: 2].
* **Fault Tolerance**: Up to 1 node offline without losing cluster availability[cite: 2].

## SRE Remediation Matrix ⚠️

Before establishing the Corosync cluster mesh, the following operational risks must be resolved:

| Target Host | Identified Risk | Technical Impact | Action Item |
| :--- | :--- | :--- | :--- |
| **Node `com`** | Virtualized ZFS over `.qcow2` on USB DAS[cite: 2] | High CPU overhead & risk of pool corruption[cite: 2] | Migrate TrueNAS VM to unprivileged SAMBA/OMV LXC with bind mounts[cite: 2] |
| **Node `dell`** | Over-allocated RAM on VM 100 (7.91 GB)[cite: 2] | Host memory starvation[cite: 2] | Trim RAM allocation to 4 GB (`qm set 100 --memory 4096`)[cite: 2] |
| **Node `com`** | PVE Version Drift (8.1.3 vs 9.2.2)[cite: 2] | Corosync RPC and migration errors[cite: 2] | Upgrade `com` to PVE 9.2.x before joining cluster
